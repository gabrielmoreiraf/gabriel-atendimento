# W5 · Interface da demo (React + Vite + TS) e design

**Objetivo:** a tela que prova que o agente **age** (anti-requisito N4: não é dashboard de métricas). Três áreas, numa única página de demo:
1. **Fila + caso:** lista da fila (`GET /api/fila`) com estado; ao abrir um caso, o chat do cliente (mensagens já mascaradas), a evidência (anexos e sinais do veredicto), a decisão da política (resultado + regra citada) e a resposta enviada ao cliente. Botão "Processar fila" (`POST /api/fila/processar`).
2. **Console dos sistemas:** o log de ações (`GET /api/acoes`) ao vivo via SSE (`/api/eventos`), com sistema, ação, valor, executor, aprovador e referência.
3. **Canal do time** (no estilo Slack, mas com marca própria, sem logo do Slack): avisos, suspeitas e pedidos de aprovação (`GET /api/canal`), com botões Aprovar/Rejeitar escolhendo o supervisor (`POST /api/aprovacoes/{id}/aprovar|rejeitar`). Mostrar o erro quando a aprovação for recusada (autoaprovação).
Mais um placar no topo (`GET /api/placar`).

**Pode editar:** `web/**`, `tokens.css`, `DESIGN.md` (raiz). Não toque em Python.

**Passos:**
1. Camada 2: invoque `impeccable` (e `ui-design:design-screen` se ajudar) para definir a direção. Crie `tokens.css` (variáveis CSS: cores, tipografia, espaçamento; tema claro e escuro) e `DESIGN.md` curto na raiz. Público: banca de hackathon num projetor; legibilidade acima de enfeite.
2. `pnpm create vite web --template react-ts` (ou equivalente não interativo), Vitest + Testing Library, Biome (`pnpm --dir web lint`), script `test`. Proxy do Vite: `/api` → `http://localhost:8000`.
3. Cliente da API tipado conforme a seção "API" do `SPEC.md`. **Enquanto o backend (W4) não sobe, use mocks locais em `web/src/mocks/`** com o mesmo formato; troque para a API real quando `curl -s localhost:8000/api/fila` responder.
4. **Nenhuma regra de negócio no front** (`decisoes/ADR-001-stack.md`): sem calcular alçada, suspeita ou prioridade. Só exibir e disparar.
5. Testes Vitest dos componentes principais; `pnpm --dir web build`, `test` e `lint` verdes.
6. Use `data-testid` estáveis (`fila-item`, `btn-processar`, `btn-aprovar`, `console-acao`, `canal-msg`, `placar`) para o E2E com Playwright do maestro.

Dados pessoais: nunca exiba CPF, telefone ou e-mail completos (a API já mascara; não remova a máscara).
**Prazo:** UI com mocks às 11:20; conectada à API real às 11:35.
