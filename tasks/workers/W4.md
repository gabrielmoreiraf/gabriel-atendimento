# W4 · Agente (orquestração) e API

**Objetivo:** o "colega": pega cada conversa da fila, entende o pedido, consulta os sistemas, chama verificação e política, executa ou pede aprovação/escala, responde o cliente e avisa o canal do time. Expõe tudo numa API FastAPI para a interface (W5).

**Pode editar:** `src/atendimento/agente/**`, `src/atendimento/api/**`, `tests/test_agente_*.py`, `tests/test_api_*.py`, `tests/fixtures/agente/**`.

**Dependências:** W1 (`atendimento.dados`, `atendimento.ferramentas`), W2 (`atendimento.politicas.decidir`), W3 (`atendimento.verificacao.verificar`). Estão sendo escritos agora em paralelo; as assinaturas estão nos arquivos `tasks/workers/W1.md`, `W2.md`, `W3.md`. Comece pelo que não depende deles e integre quando os módulos existirem (confira com `ls src/atendimento/`). Até lá, use stubs **só nos seus testes**.

**Entregas (em ordem):**
1. `atendimento.agente.leitor`: `ler(texto: str) -> Leitura` (dataclass sua) com `categoria` (avaria_vazamento, item_faltante, erro_personalizacao, reacao_adversa, rastreio, atraso, cobranca_duplicada, arrependimento, outros), `order_ids` encontrados (EC-20: mais de um pedido), `sensivel` (reação adversa: HG-06), `instrucao_embutida` (HG-09: texto que tenta mandar no agente vira só dado, sinalizado), `texto_mascarado` (HG-11: CPF `***.***.***-12`, cartão, telefone). Determinístico (regex + palavras-chave); veja exemplos reais em `ingestao/baseline_metricas.md` M10 e nos CSVs de `docs/historico_mensagens.csv`.
2. `atendimento.agente.priorizacao`: `priorizar(fila) -> list` por risco de SLA e custo do canal (HP-01; SLA e custo em `politicas.csv`/`parametros.md`).
3. `atendimento.agente.caso`: `processar(conversation_id) -> Caso`: ler mensagens → leitura → pedido → anexos → `verificar` (só para avaria/faltante/personalização) → montar `AcaoProposta` → `decidir` → executar via `Ferramentas` OU `solicitar_aprovacao` OU `sinalizar_suspeita` OU escalar (`acionar_pessoa` + ações obrigatórias) → `responder_cliente` (texto neutro, mascarado) → mensagem no canal do time. **HG-01:** o leitor propõe, a política decide. **HP-09:** todo caso termina com ação registrada ou escalação. Use o valor do item/pedido para o valor da ação (Q6: registre a escolha).
4. `atendimento.agente.aprovacoes`: aprovar/rejeitar uma aprovação pendente (o supervisor não aprova a própria ação: HG-03), executando a ação aprovada.
5. `atendimento.api.app:app` (FastAPI) com **exatamente** as rotas da seção "API" do `SPEC.md`, incluindo SSE em `/api/eventos`. Teste com `fastapi.testclient`. CORS liberado para `http://localhost:5173`. Na subida, se `var/atendimento.db` não existir, gerar via carga do W1.

**Cenários:** HP-01, HP-04, HP-09, HP-10, HG-01, HG-09, HG-11, EC-20; integração com HG-06 (AT116568 na fila) e EC-16/17 via W3.
**Prazo:** checkpoint 1 às 11:20 (leitor + API com dados reais); checkpoint 2 às **11:35** (fila inteira processada). Reporte com `worker_done` às 11:35 no máximo.
