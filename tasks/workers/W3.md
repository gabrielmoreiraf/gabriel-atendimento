# W3 · Verificador de evidência

**Objetivo:** responder "a reclamação procede?" com fatos verificáveis, antes de qualquer reenvio, troca ou reembolso por avaria, item faltante ou erro de personalização. Código **puro, sem I/O**.

**Pode editar:** `src/atendimento/verificacao/**`, `tests/test_verificacao_*.py`, `tests/fixtures/verificacao/**`.

**API pública (`atendimento.verificacao`):**
`verificar(*, pedido: Pedido, anexos: list[Anexo], anexos_mesmo_hash: dict[str, list[Anexo]], reenvios_anteriores_cliente: int, agora=AGORA) -> VeredictoEvidencia`
(`anexos_mesmo_hash`: para cada hash dos anexos da conversa, todos os anexos da base com o mesmo hash; quem busca é o W4 via repositório do W1.)

**Sinais (`TipoSinal`) a cobrir com teste:**
- **EC-15:** anexo sem EXIF gera só `SEM_EXIF` (informativo) e **nunca** torna o caso suspeito sozinho (fotos do WhatsApp chegam sem metadados: `politicas.csv`, `reclamacao_suspeita.observacao`).
- **EC-16:** mesmo `hash_perceptual` em anexo de **outro** `order_id` → `HASH_REPETIDO`.
- **EC-17:** `exif_data_captura` anterior a `pedido.data_entrega` → `CAPTURA_ANTES_DA_ENTREGA`.
- `exif_software` preenchido → `EDITOR_DE_IMAGEM`.
- **EC-18:** item personalizado cujo `texto_personalizacao` não aparece na `descricao_visual` do anexo, quando a descrição cita um nome/texto impresso → `PERSONALIZACAO_DIVERGENTE`. Seja conservador: se a descrição não fala de texto, não gere o sinal.
- **EC-19:** cliente com reenvios anteriores → `REENVIOS_ANTERIORES` (sinal de contexto; meça na base quantos reenvios são comuns e só sinalize acima de um limiar que você justificar com dados de `docs/trocas_reenvios.csv`, citando a consulta no docstring).
- **Q15 (regra de suspeita):** `suspeita = existe sinal verificável (≠ SEM_EXIF) e custo_aceitar_falso_rs > custo_sinalizar_verdadeiro_rs`, com `custo_aceitar_falso_rs = pedido.valor × 0,45` e `custo_sinalizar_verdadeiro_rs = 6.0` (`docs/parametros.md`).
- **HG-07:** `justificativa` e `Sinal.descricao` em linguagem neutra, citando fatos (anexo_id, datas), sem as palavras "fraude", "golpe", "mentira", "falso". Teste isso.

Use casos reais da base como referência para as fixtures (veja `ingestao/baseline_metricas.md`, M6), mas fixtures mínimas e sem dado pessoal.
